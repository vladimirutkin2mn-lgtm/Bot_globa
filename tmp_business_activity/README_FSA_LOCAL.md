# Росаккредитация v7: перехват реального поиска из интерфейса

Почему эта версия нужна: текущий FSA принимает обычный список документов, но INN-поля формы не являются `columnsSearch`. Поэтому v7 больше не угадывает payload.

Схема:
1. Selenium открывает настоящий Chrome/Edge и получает рабочую FSA-сессию.
2. Скрипт открывает реестр сертификатов.
3. Вы вручную один раз ищете первый тестовый ИНН через обычный интерфейс FSA.
4. Скрипт перехватывает реальный HTTP-запрос, который сформировал сам frontend.
5. То же один раз делается для деклараций.
6. После этого скрипт подставляет остальные 999 ИНН в пойманные шаблоны и выполняет запросы прямо из браузера.

## Windows

```powershell
py -m pip install -r requirements_fsa.txt
py -3.12 enrich_fsa_1000_ui_capture.py
```

Или запустите `run_fsa_windows.bat`.

## Что нужно сделать в браузере

Первый тестовый ИНН: `5445265650`.

Когда терминал напишет `НАСТРОЙКА FSA: СЕРТИФИКАТЫ`:
- в открытом FSA найдите поле поиска по ИНН;
- вставьте `5445265650`;
- нажмите Поиск / Найти;
- если есть отдельные поля «ИНН заявителя» и «ИНН изготовителя», сделайте два поиска по очереди.

Скрипт напечатает `Пойман рабочий UI-запрос #1` (и #2, если был второй вариант).

Затем откроется раздел деклараций. Повторите то же самое с тем же ИНН.

После этого начнётся автоматический прогон 1 000 компаний.

## Важно

Не закрывайте Chrome/Edge до конца работы.

Файл `output_fsa_1000/captured_search_templates.json` содержит только обезличенные шаблоны с `{INN}`, без token/cookie.

Наличие документа FSA — положительное evidence. Отсутствие документа само по себе не означает отсутствие реального бизнеса.
