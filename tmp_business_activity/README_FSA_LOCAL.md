# Росаккредитация: Selenium + API, первые 1 000 ИНН

Эта версия больше не пытается угадывать публичную FSA-сессию только через `requests`.

Схема:
1. Selenium открывает настоящий Chrome/Edge на `https://pub.fsa.gov.ru/rss/certificate`.
2. Скрипт ждёт, пока frontend FSA создаст публичную сессию.
3. Из браузера забираются cookies и фактические session/auth headers.
4. Браузер закрывается.
5. Первые 1 000 ИНН быстро проверяются через API FSA обычными HTTP-запросами.

То есть Selenium используется только для получения реальной браузерной сессии, а не для ручного кликанья по 1 000 компаниям.

## Windows

1. Установить Python 3.11/3.12 и Chrome или Edge.
2. Распаковать ZIP.
3. Открыть папку в VS Code.
4. В Terminal выполнить:

```powershell
py -m pip install -r requirements_fsa.txt
py enrich_fsa_1000_selenium.py
```

Или запустить `run_fsa_windows.bat`.

При старте откроется браузер. Не закрывайте его. Если FSA покажет проверку/согласие, пройдите её вручную. После получения сессии браузер закроется автоматически и начнётся массовый прогон.

## Результаты

Папка `output_fsa_1000`:

- `fsa_1000.csv` — итог по 1 000 ИНН;
- `fsa_1000_raw.json` — найденные документы;
- `summary.json` — сводка;
- `browser_session_debug.json` — диагностика браузерной сессии **без значений token/cookie**.

Ключевые поля:
- `ФСА статус`
- `ФСА сертификаты`
- `ФСА декларации`
- `ФСА действующие`
- `ФСА manufacturer`
- `ФСА applicant`
- `ФСА importer`
- `ФСА продукция`
- `ФСА evidence URLs`

## Если после Selenium снова 401

Пришлите:
1. последние строки Terminal;
2. файл `output_fsa_1000/browser_session_debug.json`.

В debug-файле нет самих cookies/token, там только факт их наличия, имена cookies, URL API и HTTP-статусы.

## Важно

Наличие документа FSA — positive evidence. Отсутствие документа само по себе не означает отсутствие реального бизнеса.
