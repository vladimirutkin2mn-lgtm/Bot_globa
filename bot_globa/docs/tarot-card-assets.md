# Спецификация изображений карт Tarot

Этот документ фиксирует визуальный контракт `rws-78-v1`. Карта, которую показывает Telegram, обязана соответствовать `symbol_id`, выбранному детерминированным Tarot engine. Общая иллюстрация сцены не заменяет известную карту.

## 1. Одна каноническая колода

Все расклады Numa используют единый 78-карточный Rider–Waite–Smith набор с оригинальными иллюстрациями Pamela Colman Smith для колоды Rider & Company 1909 года:

- 22 Старших Аркана;
- 56 Младших Арканов;
- Жезлы, Кубки, Мечи и Пентакли;
- в каждой масти Туз–10, Паж, Рыцарь, Королева, Король.

В продукте больше нет отдельного фирменного Numa-слоя для Старших Арканов: Major и Minor Arcana берутся из одного визуального набора. Это устраняет переход между современной фиолетово-золотой интерпретацией и классической графикой внутри одного расклада.

Оригинальные иллюстрации Rider–Waite–Smith 1909 находятся в public domain. Runtime-набор Numa — единый 720px JPEG-вариант классической колоды. Точный operational source и SHA-1 каждого установленного файла зафиксированы в `docs/tarot-rws1909-sources.json`.

## 2. Локальный набор — единственный runtime source

Все 78 изображений лежат в репозитории:

`bot_globa/app/bot/assets/tarot/`

Имена строго совпадают с card code из `app/domain/tarot.py`:

- Старшие: `major_00.jpg` … `major_21.jpg`;
- Младшие: `<suit>_<rank>.jpg`, например `cups_06.jpg`, `swords_queen.jpg`, `pentacles_king.jpg`, `wands_page.jpg`.

Приложение никогда не ходит в сеть за картой. Внешний источник используется только воспроизводимым import-script во время обслуживания ассетов; production image уже содержит всю колоду.

Смысловая привязка определяется кодом: например, `major_13.jpg` всегда относится к карте «Смерть». Переименование или перестановка файлов без изменения доменного контракта недопустимы.

`card_art()` сверяет `symbol_id` с `RWS_78_V1` до обращения к файловой системе, поэтому произвольная строка пользователя не может стать путём к файлу.

## 3. Provenance и воспроизводимость

Импортёр:

`bot_globa/scripts/import_rws1909_tarot.py`

Он устанавливает все 78 карт из одного 720px Rider–Waite набора и формирует manifest:

`bot_globa/docs/tarot-rws1909-sources.json`

Manifest содержит:

- автора оригинальных иллюстраций;
- год первой публикации;
- исходный operational repository/directory;
- соответствие source filename → локальный `symbol_id` filename;
- SHA-1 и размер каждого фактически установленного JPEG.

Тесты требуют, чтобы manifest покрывал ровно те же 78 файлов, что и `RWS_78_V1`, а SHA-1 manifest совпадал с байтами в production assets. Это защищает от незаметной замены отдельной карты другой реставрацией, recolor-версией или случайным файлом.

Современную перерисовку, recolor или коммерческую реставрацию нельзя подменять под этот набор только потому, что исходные рисунки 1909 года находятся в public domain: права на самостоятельную современную обработку проверяются отдельно.

## 4. Размер и ориентация

Любой файл должен оставаться меньше 1 МБ — это проверяет `tests/test_tarot_art.py`.

Перевёрнутые карты не требуют отдельной картинки. `orientation` и её значение передаются отдельно; изображение остаётся лицевой стороной той же карты.

## 5. Telegram delivery

`Art.key` для любой карты — `tarot:<symbol_id>`.

При первом показе карта загружается как файл (`FSInputFile`). После успешной отправки Telegram `file_id` кэшируется под тем же `Art.key`, поэтому последующие показы в рамках процесса не перезагружают файл.

Если Telegram не может принять изображение, карточный текст всё равно должен быть доставлен. Media failure не должен ломать Reading.
