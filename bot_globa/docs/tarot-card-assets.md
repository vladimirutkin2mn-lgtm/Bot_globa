# Спецификация изображений карт Tarot

Этот документ фиксирует визуальный контракт `rws-78-v1`. Карта, которую показывает Telegram, обязана соответствовать `symbol_id`, выбранному детерминированным Tarot engine. Общая иллюстрация сцены не заменяет известную карту.

## 1. Полная колода

Новые расклады работают с 78-карточной Rider–Waite–Smith колодой:

- 22 Старших Аркана;
- 56 Младших Арканов;
- Жезлы, Кубки, Мечи и Пентакли;
- в каждой масти Туз–10, Паж, Рыцарь, Королева, Король.

Перевёрнутые карты не требуют отдельной картинки. `orientation` и её значение передаются отдельно; изображение остаётся лицевой стороной той же карты.

## 2. Локальный набор — единственный источник

Все 78 изображений лежат в репозитории:

`bot_globa/app/bot/assets/tarot/`

Имена строго совпадают с card code из `app/domain/tarot.py`:

- Старшие: `major_00.jpg` … `major_21.jpg`;
- Младшие: `<suit>_<rank>.jpg`, например `cups_06.jpg`, `swords_queen.jpg`, `pentacles_king.jpg`, `wands_page.jpg`.

Приложение никогда не ходит в сеть за картой. Внешний хост не может «увести» изображение из продукта, а production image несёт всё, что нужно reveal-у.

Смысловая привязка определяется кодом; например, `major_13.jpg` всегда относится к карте «Смерть». Переименование или перестановка файлов без изменения доменной версии недопустимы.

`card_art()` сверяет `symbol_id` с `RWS_78_V1` до обращения к файловой системе, поэтому произвольная строка пользователя не может стать путём к файлу.

## 3. Два визуальных слоя

**Старшие Арканы** — фирменная Numa-версия: квадрат 1254×1254, тёмная фиолетово-золотая система, без текста на самой карте.

**Младшие Арканы** — публично-доменная графика Pamela Colman Smith (Rider–Waite, 1909), 720×1200. Слой временный: когда появится фирменный набор Младших, файлы заменяются под теми же именами. Доменная модель, engine и prompt при этом не меняются — визуальная цельность улучшается отдельно от методологии Tarot, без новой семантической версии колоды.

Любой файл должен оставаться меньше 1 МБ — это проверяет `tests/test_tarot_art.py`.

Перевёрнутые карты не требуют отдельной картинки. `orientation` и её значение передаются отдельно; изображение остаётся лицевой стороной той же карты.

## 4. Telegram delivery

`Art.key` для любой карты — `tarot:<symbol_id>`.

При первом показе карта загружается как файл (`FSInputFile`). После успешной отправки Telegram `file_id` кэшируется под тем же `Art.key`, поэтому последующие показы в рамках процесса не перезагружают файл.

Если Telegram не может принять изображение, карточный текст всё равно должен быть доставлен. Media failure не должен ломать Reading.
