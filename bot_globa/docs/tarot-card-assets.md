# Спецификация изображений карт Tarot

Этот документ фиксирует визуальный контракт `rws-78-v1`. Карта, которую показывает Telegram, обязана соответствовать `symbol_id`, выбранному детерминированным Tarot engine. Общая иллюстрация сцены не заменяет известную карту.

## 1. Полная колода

Новые расклады работают с 78-карточной Rider–Waite–Smith колодой:

- 22 Старших Аркана;
- 56 Младших Арканов;
- Жезлы, Кубки, Мечи и Пентакли;
- в каждой масти Туз–10, Паж, Рыцарь, Королева, Король.

Перевёрнутые карты не требуют отдельной картинки. `orientation` и её значение передаются отдельно; изображение остаётся лицевой стороной той же карты.

## 2. Старшие Арканы — фирменный локальный слой

Существующие 22 изображения остаются в:

`bot_globa/app/bot/assets/tarot/`

Имена строго совпадают с card code:

`major_00.jpg` … `major_21.jpg`.

Это фирменная Numa-версия Старших Арканов: квадрат 1254×1254, тёмная фиолетово-золотая система, без текста на самой карте. Файл должен оставаться меньше 1 МБ.

Смысловая привязка определяется кодом в `app/domain/tarot.py`; например, `major_13.jpg` всегда относится к карте «Смерть». Переименование или перестановка файлов без изменения доменной версии недопустимы.

## 3. Младшие Арканы — RWS fallback

Пока отдельный фирменный набор 56 Младших Арканов не нарисован, приложение использует публично-доменный Rider–Waite набор из зеркала `mixvlad/TarotCards`.

Источник закреплён на immutable revision:

`5c44ca5c94a9d67f9bc06cb6b920c2544fa76c74`

Код никогда не использует URL на moving `main`.

Сопоставление:

| Наш suit | Upstream prefix |
|---|---|
| `wands` | `Wands` |
| `cups` | `Cups` |
| `swords` | `Swords` |
| `pentacles` | `Pents` |

Ранги:

| Наш rank | Номер файла |
|---|---|
| `ace` | `01` |
| `02`…`10` | `02`…`10` |
| `page` | `11` |
| `knight` | `12` |
| `queen` | `13` |
| `king` | `14` |

Примеры:

- `cups_06` → `Cups06.jpg`;
- `swords_queen` → `Swords13.jpg`;
- `pentacles_king` → `Pents14.jpg`.

URL создаётся только после проверки `symbol_id` против `RWS_78_V1`. Произвольная строка пользователя не может стать адресом внешней картинки.

## 4. Telegram delivery

`Art.key` для любой карты — `tarot:<symbol_id>`.

При первом показе:

- локальный Major загружается как файл;
- Minor передаётся Telegram как pinned HTTPS URL.

После успешной отправки Telegram `file_id` кэшируется под тем же `Art.key`, поэтому последующие показы не зависят от повторной загрузки исходника в рамках процесса.

Если Telegram не может получить изображение, карточный текст всё равно должен быть доставлен. Media failure не должен ломать Reading.

## 5. Будущий bespoke 78-card pack

Когда появятся фирменные изображения Младших Арканов, их можно положить в локальный каталог с именами, совпадающими с `symbol_id` (`cups_06.jpg`, `swords_queen.jpg` и т. д.). `card_art()` всегда предпочитает локальный файл, поэтому доменная модель, engine и prompt при этом не меняются.

Это позволяет улучшить визуальную цельность отдельно от методологии Tarot и не создавать новую семантическую версию колоды только из-за смены изображения.
